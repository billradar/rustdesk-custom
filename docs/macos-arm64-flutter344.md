## Source and package boundaries

It executes the existing reviewed Linux bridge recipe with Flutter 3.44.8, Rust 1.75, cargo-expand 1.0.95 and FRB 1.80.1. The native build uses the official 3.44.9 SDK. The generator has Contents read only, retains the coordinator worker guard, and has no signing Environment or production signing inputs. Existing Windows ARM64 code and artifacts are unchanged. Older sources skip the generator dependencies and artifact path.

The reviewed helper changes only `flutter/lib/common.dart` and `flutter/pubspec.yaml`; the six generated bridge files are then restored. A separate receipt binds their before hashes to the immutable prepared manifest, their after hashes and bridge identity, the source variant and exact recipe. The prepared manifest is never rewritten. Subsequent recipe checks reconstruct the reviewed inputs from the exact Git HEAD, rather than treating the transformed pubspec as a new interface. Current protected recipe files must still match the prepared inventory. Native runner architecture and actual Flutter version are checked independently.

Packaging carries this receipt to aggregation. The prepared workflow hash and approved signature independently require a receipt, so clearing the new flag or claiming the older SDK cannot evade validation. A Mac ARM 3.44 package must have the matching source/custom/run/variant/toolchain and bridge receipt, as well as the existing package checksums, native API/configuration probe, architecture and actual DMG/library gates. Existing x86_64 and old-source Mac builds keep their old SDK and Flutter patch step; only the reviewed modern ARM path disables SwiftPM and omits the obsolete SDK patch.
